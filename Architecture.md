СТРОГАЯ АРХИТЕКТУРНАЯ СПЕЦИФИКАЦИЯ (САС)

Проект: Advanced CAT-Tool (Machine Translation Environment)
Версия документа: 9.1.0 (Workspace Edition: IDE-подобный интерфейс и Continuous Editor)

1. ТЕХНОЛОГИЧЕСКИЙ СТЕК (МАНДАТОРНЫЙ)

Любые отклонения от стека ЗАПРЕЩЕНЫ.

Среда (Desktop): Tauri v1.5+ (Rust-оболочка для минимального потребления RAM).

Бэкенд: Python 3.11+, FastAPI, Uvicorn.

База данных: SQLite3 (Глобальная БД + Локальные БД). Обязательное использование расширения FTS5 с паттерном External Content.

Сегментация текста (NLP): spaCy (или pysbd) для точного разбиения абзацев на предложения.

Поиск (Lorebook/Termbase): Алгоритм Ахо-Корасик (pyahocorasick) и rapidfuzz.

Фронтенд: React 18, TypeScript 5, Zustand v4+ (Global State), flexlayout-react v0.2+.

UI-Фреймворк: Tailwind CSS + shadcn/ui (Radix Primitives). Гарантирует строгую дизайн-систему, доступность (a11y), отсутствие "зоопарка" стилей и нативную поддержку тем оформления без раздувания бандла.

Виртуализация UI: react-window или react-virtuoso (для рендера только видимых сегментов).

Редактор: Slate.js + slate-history (с жестким лимитом истории).

Работа с EPUB: ebooklib (Python) или встроенная библиотека zipfile + BeautifulSoup4.

2. АРХИТЕКТУРА БАЗ ДАННЫХ, ПРОЕКТОВ И TM

Введена строгая изоляция моделей, индексы и оптимистичные блокировки.

2.1. Глобальная БД (global.sqlite)

Таблица Projects (Модель проекта)

id (TEXT, UUID, PK)

name (TEXT)

path (TEXT) - Абсолютный путь к папке проекта на диске.

source_lang (TEXT), target_lang (TEXT)

created_at (TIMESTAMP), last_opened (TIMESTAMP)

Система Translation Memory (FTS5 External Content Pattern)

Таблица tm_units (Хранилище данных):

id (INTEGER, PK, AUTOINCREMENT)

source_text (TEXT), target_text (TEXT)

source_lang (TEXT), target_lang (TEXT)

created_at (TIMESTAMP)

project_id (TEXT, UUID)

Виртуальная таблица tm_fts (Поисковый индекс):

CREATE VIRTUAL TABLE tm_fts USING fts5(source_text, content='tm_units', content_rowid='id');


Триггеры (INSERT, UPDATE, DELETE) на tm_units для синхронизации tm_fts.

Таблица Termbase (Терминологическая база)

id (PK), term (TEXT), translation (TEXT), definition (TEXT), context (TEXT).

2.2. Локальная БД проекта (project.sqlite)

Таблица Segments (Рабочая таблица)

id (PK), chapter_id (FK)

segment_index (INT)

source_text (TEXT) - Содержит inline-плейсхолдеры.

target_text (TEXT)

inline_tags (JSON) - Хранит маппинг. Пример: {"1": {"prefix": "<b>", "suffix": "</b>"}}.

status (TEXT) - Enum: NEW, TRANSLATED, EDITED, APPROVED, LOCKED.

version (INTEGER, DEFAULT 1) - Для оптимистичной блокировки.

3. СТРОГИЕ REST API КОНТРАКТЫ

3.1. Работа с сегментами (Пагинация & Optimistic UI)

GET /api/chapters/{chapter_id}/segments?offset=0&limit=50

PUT /api/segments/{segment_id}

Payload: {"target_text": "...", "status": "EDITED", "version": 5, "inline_tags": {...}}.

Optimistic Locking: Если payload.version != db.version, бэкенд возвращает 409 Conflict.

6. ВСТРОЕННАЯ WORKER-СИСТЕМА И ТМ PIPELINE

При вызове POST /api/jobs/translate-chapter, Worker выполняет каскадный пайплайн:

Этап 1: Exact TM Match (100%)

Этап 2: Fuzzy TM Match (≥ 85%)

Этап 3: Machine Translation (MT)

8. АРХИТЕКТУРА ИНТЕРФЕЙСА: WORKSPACE LAYOUT SYSTEM (НОВОЕ)

ДЛЯ РАЗРАБОТЧИКА (Jules): Этот раздел содержит строгие правила построения UI. Мы полностью отказываемся от концепции "CAT-таблицы" (как в Trados) в пользу мульти-редакторной среды, похожей на VS Code, Obsidian или Craft. Основной принцип — чистота, скругленные окна, плавно всплывающие меню и Continuous Editor.

8.1. Глобальный каркас (App Shell)

Интерфейс делится на две строгие зоны: статический каркас и динамический воркспейс.

Левая панель (Persistent Sidebar / Оглавление)

Поведение: Это постоянный элемент интерфейса (Activity Bar). Он не должен полностью исчезать с экрана или перекрывать контент (не модальный Drawer).

Состояния: * Развернутое (w-64 или ~250px): Показывает названия глав, иерархию файлов, прогресс-бары перевода для каждой главы.

Свернутое (w-16 или ~64px): Текст скрывается с плавной анимацией (transition-all duration-300 ease-in-out). Вместо длинных прогресс-баров остаются только цветные точки-индикаторы статуса (зеленая - завершено, синяя - в работе) или минималистичные иконки документов.

Механика: Переключение состояния по кнопке (иконка "Книги" / "Шеврон") или шорткатом (например, Ctrl+B).

Верхний глобальный тулбар (Header)

Минималистичная полоса сверху (высота ~h-12 или h-14).

Содержит только глобальную информацию: название проекта, статус синхронизации (сохранено/ошибка) и вызов глобальных настроек макета. Никаких инструментов редактирования здесь быть не должно.

8.2. Динамический Воркспейс (flexlayout-react)

Основная область управляется библиотекой flexlayout-react. Пользователь может открывать, закрывать, разделять (split horizontal/vertical) и перетаскивать окна по принципу drag-and-drop.

Базовая сущность: Pane (Панель/Окно).

Типы панелей:

editor_pane (Основной редактор для перевода: RU → JP)

reference_pane (Только для чтения: исходный текст или другой язык для сравнения)

tm_pane (Память переводов и конкорданс)

termbase_pane (Глоссарий)

Сохранение (Layout Persistence): Состояние макета (размеры окон, их положение) должно сохраняться в layout.json в Workspace проекта и восстанавливаться при перезапуске.

8.3. Дизайн и UX Панелей (Panes)

Каждая панель (Pane) внутри воркспейса должна выглядеть как современное "окно" или "карточка", а не как ячейка таблицы.

Визуальный стиль окон:

Большие текстовые области с выраженными скруглениями (rounded-xl или rounded-2xl).

Разделение окон через фон (фон приложения — светлый/темный серый, например bg-slate-100, а сами окна — bg-white с легкой тенью shadow-sm).

Header панели (Заголовок окна):

У каждого окна есть свой собственный Header.

Левая часть Header-а: Языковой тег (например, стилизованный бейдж "RU" или "EN") и название (например, "Оригинал" или "Перевод").

Правая часть Header-а (Контекстные инструменты): Кнопки "Быстрый перевод (MT)", "Умный перевод (LLM)" и другие действия.

Скрытые меню и анимации:

Чтобы не перегружать интерфейс, дополнительные действия и меню (например, настройки конкретного MT движка, история версий) должны быть скрыты за ярлыками (иконка с тремя точками MoreVertical).

Появление меню должно происходить по клику или наведению (hover) с плавной CSS анимацией (opacity, transform: translateY).

8.4. Парадигма Continuous Editor (Сплошной текст)

Это самое важное отличие от классического CAT-тула.

Текст внутри editor_pane или reference_pane должен рендериться как сплошной, непрерывный документ (Continuous flow), сохраняя абзацы, пустые строки и структуру книги (как в Notion или MS Word).

Никаких табличных границ (border) между предложениями.

Синхронизация по фокусу (Cursor Sync): * Сегментация (разбивка на предложения) скрыта "под капотом".

Когда пользователь кликает на предложение в целевом тексте (Target), это предложение становится "Активным сегментом".

Активный сегмент визуально выделяется (например, легким фоном, тенью или акцентной рамкой слева).

Критично: При смене активного сегмента в editor_pane, соседняя панель reference_pane (Оригинал) должна автоматически проскроллиться и выделить соответствующее предложение оригинала. Панели tm_pane и termbase_pane мгновенно обновляют свои данные под активный сегмент.

8.5. Статусы и Микроинтеракции (Microinteractions)

Визуальная обратная связь должна быть деликатной, но очевидной:

Состояния перевода: Вместо тяжелых цветных блоков используем элегантные индикаторы (например, иконка статуса слева от предложения: зеленая галочка — Approved, желтая искра — AI translated).

Скелетоны при загрузке: При вызове AI-перевода ("Умный перевод") вместо подвисания интерфейса или спиннеров на весь экран, в области текста должен плавно появиться Skeleton loader (анимация пульсации animate-pulse), имитирующий длину будущего текста.

Фокус-режим (Zen Mode): По шорткату все панели, кроме центрального редактора, скрываются, левый сайдбар сворачивается до узкой полосы, позволяя переводчику полностью погрузиться в текст.
